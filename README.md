# NotiHub

## О проекте

NotiHub - сервис доставки уведомлений с HTTP API и подключаемыми каналами отправки (email, webhook, push): API мгновенно сохраняет уведомление и отвечает клиенту, а саму доставку через очередь на Kafka выполняет отдельный воркер.

## Основные функции

- **Приём уведомлений:** `POST /notifications` сохраняет уведомление со статусом pending и сразу возвращает ответ, не дожидаясь фактической отправки.
- **Каналы доставки:** email, webhook и push подключаются через общий интерфейс отправителя и его реестр.
- **Асинхронная доставка через очередь:** API публикует ID уведомления в Kafka, а `notihub-worker` забирает задание и выполняет отправку - это позволяет масштабировать доставку независимо от API, запуская несколько воркеров в одной consumer-группе.
- **Повторные попытки:** при сбое доставка повторяется с экспоненциальной задержкой и джиттером, пока не исчерпает лимит попыток; итоговый статус, число попыток и текст последней ошибки можно посмотреть через `GET /notifications/{id}`.
- **Идемпотентная обработка:** повторная доставка одного и того же задания из очереди (at-least-once) не приводит к повторной отправке уже обработанного уведомления.
- **Ограничение запросов:** rate limiting на клиента по IP с настраиваемым лимитом и burst.

## Хранилище

Данные лежат в PostgreSQL. Драйвер - jackc/pgx (через database/sql-совместимость pgx/v5/stdlib), чистый Go без CGO, так что бинарник по-прежнему собирается статически.

Схема лежит в `internal/repository/migrations` и вшита в бинарник через embed. Непримененные миграции накатываются при старте и фиксируются в таблице `schema_migrations`.

## Компоненты

- **cmd/notihub:** HTTP API - принимает запросы, сохраняет уведомления и публикует задачи на доставку.
- **cmd/notihub-worker:** консьюмер очереди - выполняет доставку и обновляет статус уведомления.
- **internal/service:** создание уведомлений и логика доставки с повторными попытками.
- **internal/provider:** каналы доставки (email, webhook, push) и их реестр.
- **internal/queue:** продюсер и консьюмер Kafka.
- **internal/repository:** хранилище на PostgreSQL и миграции схемы.
- **internal/transport:** HTTP-роутинг и middleware.
- **internal/ratelimit:** ограничитель запросов по клиенту.
- **internal/config:** чтение конфигурации из переменных окружения.

## Установка и запуск

1. **Клонируйте репозиторий:**

    ```bash
    git clone https://github.com/PakSerg/NotiHub.git
    cd NotiHub
    ```

2. **Настройте переменные окружения (при необходимости):**

    Сервис работает с настройками по умолчанию из `compose.yaml`. Переопределить адрес БД, брокеры Kafka, лимиты запросов и политику повторов можно через окружение - полный список переменных смотри в `internal/config`.

3. **Запустите проект:**

    ```bash
    docker compose up --build -d
    ```

    Поднимутся четыре контейнера: API (`notihub`), воркер (`notihub-worker`), PostgreSQL и Kafka.
